# PDF forms

Use this reference when the user wants to enter values into a PDF. Determine what sort of form it is before writing anything; a printed blank on a scanned page is not an interactive PDF field.

1. **Inspect first.** Render the relevant pages and look at the form. With `pypdf`, `PdfReader(path).get_fields()` exposes AcroForm field names and types when present. Inspect field options and page widgets, not just their names: identical-looking blanks can represent different questions. An empty field list may mean a flat form, unsupported XFA content, or a nonstandard PDF; do not assume it is safe to overlay text without looking.
2. **Map values explicitly.** Ask for any missing or ambiguous answers. Never infer personal details, consent, checkbox choices, or a signature from context. Check the actual allowed states for buttons and choices; do not assume a particular "checked" value. Keep sensitive values out of console output and avoid persistent scratch files unless needed.
3. **For AcroForms, retain the form structure.** Write a task-specific `pypdf` script (use `uv run --no-project --with pypdf ...` outside existing Python projects). Use `PdfWriter.append(reader)` to preserve fields; copying individual pages with `add_page` alone can lose the document-level form tree. Call `writer.update_page_form_field_values(writer.pages[page_index], values_for_that_page, auto_regenerate=False)` for the appropriate page(s), then write a *new* PDF. Match full field names and check failures rather than silently dropping an unknown field. The [pypdf forms guide](https://pypdf.readthedocs.io/en/stable/user/forms.html) explains field/widget differences and appearance behavior.
4. **For printed blanks, compose an overlay only if placement can be checked.** Render the page, locate the blanks, then add text/marks using a PDF drawing library and merge with the original page. PDF coordinates usually start at the bottom-left; image pixel coordinates usually start at the top-left, and page rotation/crop boxes can change the mapping. Test one page before doing a batch. This creates visible marks, **not** fillable fields.
5. **Verify at both levels.** Reopen a filled AcroForm and inspect the stored values, then render every affected page to check appearance, clipping, choice marks, and placement. Some viewers render form appearances differently. With `pypdfium2`, call `PdfDocument.init_forms()` before rendering a page, or fields can look blank even when the values were saved. If flattening is requested, verify it separately: a printable copy and an editable copy serve different purposes.

Edits generally invalidate existing digital signatures; do not alter a signed document without explicit agreement. XFA and complex dynamic forms may require different software. This skill intentionally has no one-size-fits-all form-filling script: the field map and layout must be validated against the specific PDF.
